-------------

COMO PUBLICAR (ATUALIZADO — deploy via Vercel, não mais FTP/cPanel)
---------------------------------------------------------------------
Este repositório é importado como projeto na Vercel e publicado a cada
push na branch principal — não existe mais upload manual de arquivo nem
cache de CDN externo para limpar.

1. `git push` na branch principal deste repositório dispara o deploy
   automático na Vercel.
2. O projeto Vercel tem três domínios apontando para ele:
   - institutofacaamigos.com.br (+ www) → serve index.html, que é o hub
     (comportamento padrão da Vercel, sem lógica nenhuma — decisão
     deliberada: o domínio mais importante não deve depender de nenhuma
     regra condicional para funcionar).
   - playground.institutofacaamigos.com.br → serve playground.html via
     Routing Middleware (middleware.js), que reescreve "/" para
     "/playground" só quando o Host é esse subdomínio. `has: [{type:
     "host", ...}]` em rewrites do vercel.json NÃO é uma condição válida
     na API da Vercel (só existe `header` e `cookie`) — não usar essa
     abordagem de novo.
3. Confirme que os seguintes endereços ficam acessíveis publicamente após o
   deploy:
   - https://institutofacaamigos.com.br/
   - https://playground.institutofacaamigos.com.br/
   - https://playground.institutofacaamigos.com.br/politica-privacidade.html
   - https://playground.institutofacaamigos.com.br/robots.txt
   - https://playground.institutofacaamigos.com.br/sitemap.xml
   - https://playground.institutofacaamigos.com.br/google877c2b37d3c979fb.html
     (esse arquivo é de verificação do Google Search Console — não mexer no
     conteúdo dele, ele precisa ficar exatamente como está)
4. Não é preciso limpar cache manualmente: cada deploy da Vercel já invalida
   a CDN. Ver runbook completo em faca_amigos/docs/INFRA_DOMINIO_EMAIL.md
   para o mapa de domínios e o histórico da migração do Netlify.

TESTE DE COMPORTAMENTO + PAINEL DA IDEALIZADORA (14/09/2026)
====================================================================

O QUE É
--------
`/teste` é um quiz de captação de leads: pais respondem sobre o
comportamento do filho, veem um retrato inicial na tela e a
idealizadora recebe o lead por e-mail (Brevo) para prospectar a
Clínica. `/admin` é o painel privado dela para ver todos os leads,
gerar um resumo com IA (Google Gemini) sobre cada resultado e
reenviar esse resumo ao responsável por e-mail.

ARQUIVOS NOVOS
----------------
- teste.html            → landing + quiz (público)
- teste-perguntas.json  → perguntas/faixas do quiz (editável sem deploy
                           de função; ver abaixo)
- admin.html            → painel da idealizadora (login + lista de leads)
- supabase/functions/behavior-test-webhook/  → recebe as respostas do quiz
- supabase/functions/behavior-test-admin/    → login, listagem, insight IA
- supabase/migrations/20260914*.sql          → tabelas no Supabase

BANCO (projeto Supabase ivjvpdzsfjdpyabbzzuj)
-------------------------------------------------
- fa_leads_teste_comportamento → um registro por família (RLS ligado,
  sem policy pra anon — só as Edge Functions, via service role, leem
  e escrevem).
- fa_teste_admin_users / fa_teste_admin_sessions → login do painel.

TROCAR O CONTEÚDO DO TESTE (perguntas/faixas reais)
--------------------------------------------------------
1. Editar teste-perguntas.json (perguntas, escala de respostas, faixas
   de resultado). Trocar "version" para uma data nova quando o
   conteúdo mudar de verdade.
2. Copiar a MESMA lista de perguntas (QUESTION_IDS) e faixas (BANDS) e
   o mesmo "version" (TEST_VERSION) para dentro de
   supabase/functions/behavior-test-webhook/index.ts — o score é
   sempre recalculado no servidor, nunca confia no que vem do
   navegador. Se as versões não baterem, o site pede pra recarregar.
3. Reimplantar a função (`deploy_edge_function` via MCP, ou
   `supabase functions deploy behavior-test-webhook` pela CLI).

SECRETS QUE PRECISAM SER CONFIGURADOS NO SUPABASE
-------------------------------------------------------
Painel do projeto → Edge Functions → Secrets (ou `supabase secrets set`):
- BREVO_API_KEY          → mesma chave usada nos outros apps FaçaAmigos
- BREVO_FROM             → "Instituto Faça Amigos <instituto@institutofacaamigos.com.br>"
- BREVO_REPLY_TO         → e-mail que deve receber respostas dos pais
- LEAD_NOTIFY_EMAIL      → e-mail da idealizadora, que recebe cada lead
- GEMINI_API_KEY         → chave da Google Gemini API (mesma família de
                           chave usada em Clínica FaçaAmigos/lib/gemini.ts
                           e no Kiosk) — sem ela, o botão "Gerar insight
                           com IA" do painel retorna erro, mas o resto do
                           fluxo continua funcionando normalmente.
- ADMIN_BOOTSTRAP_SECRET → segredo inventado por você, só serve para
                           criar/resetar a senha do painel (ver abaixo).

Sem BREVO_API_KEY/LEAD_NOTIFY_EMAIL configurados, o lead continua
sendo salvo no banco normalmente — só o e-mail de aviso falha
(fica registrado em email_error na tabela).

CRIAR/RESETAR O LOGIN DA IDEALIZADORA NO PAINEL (/admin)
--------------------------------------------------------------
1. Defina ADMIN_BOOTSTRAP_SECRET nos secrets da função
   behavior-test-admin (qualquer texto forte, só você e quem for
   configurar precisa saber).
2. Rode (troque SEGREDO, EMAIL e SENHA):

   curl -X POST https://ivjvpdzsfjdpyabbzzuj.supabase.co/functions/v1/behavior-test-admin \
     -H "Content-Type: application/json" \
     -d '{"action":"bootstrap","bootstrap_secret":"SEGREDO","email":"EMAIL@institutofacaamigos.com.br","password":"SENHA_COM_8_OU_MAIS_CARACTERES"}'

3. Esse mesmo comando também RESETA a senha se rodar de novo com o
   mesmo e-mail — é assim que ela troca a senha se esquecer.
4. Login em https://institutofacaamigos.com.br/admin com esse e-mail
   e senha (sessão dura 12h).
